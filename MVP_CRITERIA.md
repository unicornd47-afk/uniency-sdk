# uniency Universal SDK: measurable MVP criteria (draft r10.2, option b, licence Apache-2.0 OR MIT, 14:21, uni · KI-Forschung)

Status: DRAFT for the "uniency Universal SDK (Rust)" room. Nothing built or measured. All numbers are proposed TARGETS, not measured values. Measurement only once there is code, and not on the box while an exp001 arm runs.
Basis: EVIDENCE.md ff410ae2…c492 (which CEWP figures are measured and which are not). CEWP numbers are never adopted as SDK properties.

## 0. Rules for every benchmark
- Reproducible: `cargo bench` (criterion) plus a script that pins its inputs. Each result carries the commit SHA, rustc version, host fingerprint (CPU model, cores, RAM), thread count and date. Raw data (criterion JSON) gets a sha256.
- Reference hosts: (H1) laptop unicorn CPU, (H2) Raspberry Pi (aarch64). Numbers only count per host, never across hosts.
- Reported as median plus p95 over ≥ 30 repetitions (criterion default), after warm-up. A criterion counts as met only if p95 meets the target.
- Each criterion is tagged: [L] gate for the MVP, [H] reported only.

## 1. Identity and signatures (core)
- I1 [L] Correctness: Ed25519 passes all RFC 8032 test vectors. ML-DSA-65 passes the NIST FIPS 204 ACVP/KAT vectors. 0 failures.
- I1a [L] The ML-DSA backend is pinned exactly (`ml-dsa = "=0.1.1"`, RustCrypto, Apache-2.0/MIT, pre-1.0). I1 runs against exactly this version; a version change repeats I1. The MVP result must carry the label 'ML-DSA backend not audited'.
- I1b [L] Own wire format (option b): the SDK ships its own versioned test vectors (`vectors/v1/*.json`, sha in the release) generated by an independent second implementation (e.g. Python `cryptography` + a reference ML-DSA), and the core reproduces every vector. CIRIS interop is not a core criterion; it is tested only in the separate AGPL adapter (A4).
- I2 [L] Hybrid rule (bound hybrid; own clean-room implementation of the construction, no code taken from AGPL sources; a construction is not copyrighted, code is): data = `u8 version || u16 len || ctx || msg`; ed = Ed25519 over data, pq = ML-DSA-65 over `data || ed_sig`. Valid only if both are valid. A test matrix of 4 cases (both ok, one broken each, both broken) gives exactly 1 accept. Extra test: a valid ed_sig swapped for another valid ed_sig over the same data invalidates pq (binding holds). Without `pqc-ml-dsa` our crate fails with `compile_error!`; this is checked as a compile-fail test (`trybuild`). Independently, `verify` returns `Err` whenever no PQ backend is linked (unit test with a mock backend registry), so Ed-only is never accepted. The wire codec is our own versioned format (version byte, length-prefixed fields, trailing bytes rejected, decoder included in the I4 fuzzing) until CIRIS replaces the placeholder `to_bytes`; I1b compares only once CIRIS vectors exist.
- I3 [L] Negative tests: a bit flip in the message, signature or public key; a wrong algorithm in the header; a truncated signature; replay with an old nonce or expired timestamp. Every case is rejected, with a defined error code and no panic.
- I3b [L] Every negative case from PhaseMirror's model is rejected, with one test each: only one half valid; halves swapped between keys or messages; ed_sig swapped while pq is unchanged (I2 binding); pq unbound, only over data; token with trailing bytes after the last field; context missing because the caller forgot it (the SDK prepends it, never the caller); wrong context string (e.g. `uniency/login/v1` vs. a different purpose); nonce reused, including after a process restart; nonce under 128 bits; wrong audience, key id or context; challenge older than 60 s or outside the fixed clock-skew limit; revoked key; revocation state unknown or older than the maximum age; downgrade (PQ half stripped while the identity row demands hybrid); malleable Ed25519 signature (verify_strict). Acceptance only for accept = ed ∧ pq ∧ ¬revoked ∧ fresh, checked as a property test across all 2^4 combinations.
- I4 [L] Fuzzing: `cargo fuzz` on token parsing and verify, ≥ 1 h per target on H1, 0 crashes, 0 panics.
- I5 [H] Speed: sign and verify for each algorithm on H1 and H2. Proposed target: hybrid verify p95 ≤ 2 ms on H2 (confirmed only once measured).
- I5b [H] Measurement protocol for I5, I7 and B4: release build, pinned CPU frequency or the governor reported, 200 warmup runs then 10,000 measured, p50/p95/p99 with raw CSV, host and commit in the header. 3 repetitions; a value counts only if the p95 values of the repetitions are within 10% of each other.
- I7 [H] Keystore round-trip (create, store, load, sign) on H1 and H2, p95 reported. Load after a process restart gives an identical public key and a verifiable signature (correctness [L]).
- I6 [L] No secret leaves the process. Keys stay in OS storage or a file with 0600 permissions, and a test checks the permissions. Secret types implement Zeroize (code review plus test).

## 2. Agent API
- A1 [L] Stable interface: a versioned API surface (e.g. `uniency-core` 0.1), checked by `cargo public-api` or semver-checks in CI. No break without a version bump.
- A2 [L] Halt mechanism: a stop signal reaches a running agent loop in ≤ 100 ms p95 on H1. Afterwards no further tool or model step runs (a test with a step counter). PhaseMirror defines the security model; this criterion only measures that it holds.
- A2b-1 [L] Forged halt row (invalid signature, wrong context, or unauthorized signer): discarded and logged, halt state unchanged, the agent keeps running (one test per case).
- A2b-2 [L] Resume: a forged resume, one signed with the agent's own key or a roster key, one without the hash of the halt it lifts, or one with an epoch not higher than the halt's leaves the agent halted (one test per case). An unknown or unreadable halt state counts as halted. The halt check sits in the dispatch path of every step (a test with a step counter and no poller running). Runs offline under M1 conditions.
- A2b-3 [H] After a halt, a signed halt_ack goes into the trace (halt hash plus last step counter). A later step event shows up as a violation in the hash-chain check. Evidence only, not proof.
- A2c [L] Process boundary to the BUSL service (UtoPiCorn_LM): unsigned, replayed and halted requests are rejected before the service acts (one test each).
- A3 [L] Every agent step writes a trace event (see T1). Test: N steps produce exactly N events.

## 3. Local models (GoldWorm)
- M1 [L] Offline: all MVP tests pass with no network (namespace or `unshare -n`), and no network socket is opened (test via strace or seccomp log).
- M2 [L] Numerical equivalence: GoldWorm v8 (rev c0dc0f13) inference in the SDK reproduces the PyTorch reference on 32 fixed prompts. Greedy bytes are identical, max |Δlogit| ≤ 1e-3 in fp32.
- M3 [H] Throughput: bytes/s and time to first byte on H1 and H2, plus peak RSS. Reported against the PyTorch reference on the same host.
- M4 [H] The .gw (3-bit GW01) load path reproduces the published reference results for the .gw file. No new quality claim.

## 4. Traces and telemetry
- T1 [L] Local only: the default is a local file (JSONL or SQLite). Export is opt-in, and a test checks that the default config sends nothing.
- T2 [L] Integrity: trace events are hash-chained and optionally signed with the identity from §1. A test shows that a manipulated event is detected.
- T3 [H] Overhead: tracing on vs. off, agent loop with 1000 steps, relative overhead reported. Proposed target ≤ 5% (confirmed only once measured).

## 5. Bindings (thin layers)
- B1 [L] PyO3, napi and WASM each pass the same conformance suite (I1–I3, A2, M2 on 4 prompts) with identical results to the Rust core.
- B2 [H] The binding layer contains no logic of its own. Lines of code per binding are reported, and every business rule lives in the core (review by dahill).
- B4 [H] Binding overhead: hybrid verify through PyO3 minus the Rust core, same protocol as I5b, on H1 and H2. Reported as absolute µs and %. No target in the MVP, only reported.
- B3 [H] The WASM build has no file system or network by default. Size of the .wasm is reported.

## 6. License and supply chain
- L1 [L] Option b (Gerrit 2026-11-11): the core is licensed `Apache-2.0 OR MIT` (decided by Kiri on Gerrit's delegation, SDK_DISCUSSION Q0): every core crate has `license = "Apache-2.0 OR MIT"` plus LICENSE-APACHE and LICENSE-MIT; a test checks all core manifests. `cargo deny` in CI with an allow-list of permissive licences only (MIT, Apache-2.0, BSD-2/3, ISC, Unicode-3.0, Zlib, CC0); every AGPL/GPL/LGPL/BUSL/SSPL licence is denied. deny.toml keeps `[[licenses.clarify]]` pinning the 7 cewp crates (kernel, adversary, evidence, cli, kernel-wasm, csd4, sim) and ciris-* to AGPL-3.0-or-later (dahill FACTCHECK eed04390), so a mislabelled manifest cannot slip through. Negative tests: a probe crate depending on a cewp crate and one depending on ciris-crypto must both fail CI. Graph test: `cargo tree -e normal,build` of every core crate contains no cewp-*, ciris-* or BUSL crate. Copyleft is rejected, not warned (`[licenses] allow` only; AGPL/GPL/LGPL absent). `cargo deny check licenses` runs on `--all-features` AND on the default graph. `[bans] deny` lists `ciris-*` and `cewp-*` for the core. Process-boundary test: the adapter is its own binary in its own workspace and `cargo tree -p <core crate>` (all features) does not contain it. Clean room: the core is written only from the specification (this file + I2/I3b), nothing is copied from `src_ref/` (AGPL); dahill's review includes a diff/similarity check against `src_ref/`. Signatures: `ed25519-dalek` (BSD-3) and `ml-dsa =0.1.1` (Apache-2.0/MIT) directly; licences [H] until `cargo deny` confirms. The `rev = "cbcd9576…"` pin applies only to the adapter.
- A4 [L] CEWP/CIRIS adapter: a separate binary/crate (`uniency-cewp-adapter`, AGPL-3.0-or-later, own repo/workspace) that talks to the core only over a process boundary (IPC with the SDK's own wire format: stdin/stdout or a Unix socket), never by linking. ciris-* pinned by `rev = "cbcd9576…"` (tag v22.0.0) with `cargo tree -d` duplicate check there. Test: the core builds, tests and ships with the adapter absent; the adapter's I1b-interop vectors (CIRIS, if published) run only in the adapter's CI. Interop: core signs, adapter verifies with ciris-crypto, and the reverse, with mirrored negative cases; every format translation in the adapter has a roundtrip test. Optional for the MVP.
- L2 [L] `cargo audit` shows 0 known vulnerabilities at release. SBOM (CycloneDX) attached.
- L3 [H] Reproducible build: two builds on the same host with the same toolchain give the same artifact hash (reported, not a gate).

## 7. MVP gate
MVP = I1–I4 (incl. I3b), I6, A1–A3 (incl. A2b-1 and A2b-2; A2c only if the BUSL service is part of the MVP), M1–M2, T1–T2, B1 (at least PyO3), L1–L2 all PASS on H1 (A4 optional), plus I1–I3, M1 and M2 on H2. [H] numbers go into a results table with raw data. No public release without Dark's OK.
